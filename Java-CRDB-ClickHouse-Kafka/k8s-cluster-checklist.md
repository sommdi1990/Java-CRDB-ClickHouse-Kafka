# راهنمای مشاهده وضعیت و عیب‌یابی کلاستر Kubernetes

این فایل شامل: 1. دستورات مشاهده وضعیت نودها و سرویس‌ها 2. نحوه گرفتن لاگ
و توضیحات کامل منابع 3. چک‌لیست عیب‌یابی در دو فاز: - فاز ۱: بررسی سریع و
سبک - فاز ۲: بررسی دقیق و پیشرفته

------------------------------------------------------------------------

# بخش اول --- مشاهده وضعیت منابع کلاستر

## مشاهده لیست همه Nodeها

نمایش ساده وضعیت نودها:

``` bash
kubectl get nodes
```

نمایش با جزئیات بیشتر (IP، نسخه، نقش و ...):

``` bash
kubectl get nodes -o wide
```

نمایش توضیحات کامل یک نود:

``` bash
kubectl describe node <node-name>
```

------------------------------------------------------------------------

## مشاهده همه Serviceها

نمایش همه سرویس‌ها در همه Namespaceها:

``` bash
kubectl get svc -A
```

نمایش سرویس‌های یک namespace خاص:

``` bash
kubectl get svc -n kube-system
```

با جزئیات بیشتر:

``` bash
kubectl get svc -A -o wide
```

------------------------------------------------------------------------

## مشاهده همه Podها

``` bash
kubectl get pods -A
```

با نمایش IP و Node:

``` bash
kubectl get pods -A -o wide
```

مانیتور لحظه‌ای:

``` bash
kubectl get pods -A -w
```

------------------------------------------------------------------------

## گرفتن لاگ از Pod

``` bash
kubectl logs <pod-name> -n <namespace>
```

در صورت داشتن چند کانتینر:

``` bash
kubectl logs <pod-name> -c <container-name> -n <namespace>
```

لاگ اجرای قبلی (برای CrashLoopBackOff):

``` bash
kubectl logs <pod-name> -n <namespace> --previous
```

------------------------------------------------------------------------

## مشاهده توضیحات کامل یک Pod

``` bash
kubectl describe pod <pod-name> -n <namespace>
```

بخش Events معمولاً دلیل دقیق خطا را مشخص می‌کند.

------------------------------------------------------------------------

## مشاهده همه منابع مهم

``` bash
kubectl get all -A
```

نمایش همه نوع Resourceهای قابل استفاده:

``` bash
kubectl api-resources
```

------------------------------------------------------------------------

## بررسی منابع نصب شده با Helm

``` bash
helm list -A
```

جزئیات یک Release:

``` bash
helm status <release-name> -n <namespace>
```

------------------------------------------------------------------------

# بخش دوم --- چک‌لیست عیب‌یابی کلاستر

# فاز ۱ --- بررسی سریع و سبک (Quick Health Check)

این فاز برای زمانی است که می‌خواهید سریع بفهمید کلاستر سالم است یا نه.

### مرحله ۱: بررسی وضعیت نودها

``` bash
kubectl get nodes
```

اگر نودی NotReady بود:

``` bash
kubectl describe node <node-name>
```

------------------------------------------------------------------------

### مرحله ۲: بررسی Podهای مشکل‌دار

``` bash
kubectl get pods -A
```

دنبال وضعیت‌های زیر بگردید: - CrashLoopBackOff - ImagePullBackOff -
ErrImagePull - Pending

------------------------------------------------------------------------

### مرحله ۳: بررسی لاگ Pod مشکل‌دار

``` bash
kubectl logs <pod-name> -n <namespace> --previous
```

------------------------------------------------------------------------

### مرحله ۴: بررسی Eventهای کلاستر

``` bash
kubectl get events -A --sort-by=.metadata.creationTimestamp
```

------------------------------------------------------------------------

### مرحله ۵: بررسی سرویس‌های سیستمی

``` bash
kubectl get pods -n kube-system
```

اطمینان حاصل کنید: - CoreDNS در حال اجراست - kube-proxy سالم است - CNI
(مثل Calico) سالم است

------------------------------------------------------------------------

# فاز ۲ --- بررسی دقیق و پیشرفته (Deep Troubleshooting)

این فاز برای زمانی است که مشکل پیچیده‌تر است.

------------------------------------------------------------------------

## ۱. بررسی منابع مصرفی نودها

``` bash
kubectl top nodes
```

بررسی مصرف Podها:

``` bash
kubectl top pods -A
```

اگر نصب نیست:

``` bash
kubectl get deployment metrics-server -n kube-system
```

------------------------------------------------------------------------

## ۲. بررسی وضعیت شبکه

بررسی Podهای CNI:

``` bash
kubectl get pods -n calico-system
```

بررسی لاگ CNI:

``` bash
kubectl logs <calico-pod> -n calico-system
```

------------------------------------------------------------------------

## ۳. بررسی وضعیت کنترل‌پلین

``` bash
kubectl get pods -n kube-system -o wide
```

اگر kube-apiserver یا etcd مشکل داشت:

``` bash
kubectl describe pod <control-plane-pod> -n kube-system
```

------------------------------------------------------------------------

## ۴. بررسی Image Pull از رجیستری خصوصی

اگر ErrImagePull دارید:

- بررسی دسترسی DNS
- بررسی ImagePullSecret
- بررسی دسترسی شبکه به رجیستری

تست دستی روی نود:

``` bash
ctr images pull <image-name>
```

------------------------------------------------------------------------

## ۵. بررسی وضعیت Helm Release

``` bash
helm status <release-name> -n <namespace>
```

بررسی مانفیست کامل:

``` bash
helm get all <release-name> -n <namespace>
```

------------------------------------------------------------------------

## ۶. بررسی کامل یک Namespace

``` bash
kubectl get all -n <namespace>
kubectl describe all -n <namespace>
```

------------------------------------------------------------------------

# ترتیب پیشنهادی عیب‌یابی حرفه‌ای

1. Node Ready؟
2. Pod Running؟
3. Events چه می‌گویند؟
4. Logs چه می‌گویند؟
5. Resource کمبود دارد؟
6. شبکه سالم است؟
7. رجیستری در دسترس است؟
8. Helm Release سالم است؟

------------------------------------------------------------------------

# جمع‌بندی

فاز ۱ برای تشخیص سریع مشکل است. فاز ۲ برای تحلیل ریشه‌ای و حرفه‌ای مشکل
استفاده می‌شود.

این چک‌لیست را می‌توانید به عنوان مرجع دائمی نگه دارید و در هر دیباگ
مرحله‌به‌مرحله جلو بروید.
